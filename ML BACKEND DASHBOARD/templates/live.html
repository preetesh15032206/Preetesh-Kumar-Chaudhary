1 The Architecture & Flow

This project is an end-to-end Machine Learning ETL (Extract, Transform, Load) pipeline and visualization dashboard. The pipeline operates in 3 distinct steps:

  • Ingest: Pulls raw hourly weather data from an external weather API.
  • Transform & Train: Cleans the data, engineers new mathematical features, and trains a Machine Learning model.
  • Predict & Serve: Generates next-hour temperature predictions and serves everything via a Node.js API to a React frontend.
3 Database (Where the data lives)

The project uses SQLite (pipeline.db) as a lightweight, serverless relational database. It contains three main tables:

  • raw_weather: Stores the raw historical weather data exactly as it comes from the Open-Meteo API.
  • predictions: Stores the ML model's predicted temperatures alongside the actual observed temperatures so we can graph the difference (Actual vs. Forecast).
  • eval_log: Every time the model is retrained, it logs its accuracy metrics here (MAE, RMSE, and the number of training samples used). This powers the "Evaluation History" page to monitor model drift over time.
2 External API (Where the data comes from)
Open-Meteo API Endpoint

API Key: None required. Open-Meteo is a free, open-source weather API that does not require an API key for standard non-commercial usage.

What it fetches: It grabs the last 14 days of historical hourly weather data, plus a 1-day forecast. The variables collected are: Temperature, Relative Humidity, Wind Speed, Precipitation, and Apparent (Feels-Like) Temperature.

4 Machine Learning Pipeline (How the model works)
A. FEATURE ENGINEERING

Before the model can learn, the Python script (scripts/model.py) transforms the raw data into smarter variables:

  • Time Encoding: Converts the hour into Sine and Cosine waves. (This is a clever ML trick so the model understands that 23:00 and 00:00 are right next to each other, mathematically creating a continuous circle of time).
  • Lag Features: Looks backward in time. It adds columns for what the temperature, humidity, and wind were exactly 1, 2, and 3 hours ago.
  • Rolling Averages: Calculates the 3-hour and 6-hour moving average of the temperature to smooth out temporary spikes.
  • The Target: Takes the temperature and shifts it backwards by 1 hour. This teaches the model to look at current conditions and predict the next hour.
B. THE MODEL USED
Algorithm: Random Forest Regressor (via scikit-learn).

How it works: A Random Forest is an "ensemble" algorithm. It builds 100 different Decision Trees, each looking at a random subset of the weather data. When asking for a prediction, all 100 trees make a guess, and the forest averages them out to give a highly accurate, stable prediction.

Evaluation metrics:
- MAE (Mean Absolute Error): On average, how many degrees off is the model?
- RMSE (Root Mean Squared Error): Similar to MAE, but heavily penalizes the model for being very wrong on a single prediction.

5 Tech Stack & Dependencies
Python (The ML Backend)
requests Fetch data from Open-Meteo API.
pandas Manipulate DataFrames and calculate rolling averages.
scikit-learn Build Random Forest, scale data, calculate MAE/RMSE.
numpy Mathematical operations like Sine/Cosine calculations.
joblib Serialize and save the trained model to disk (model.joblib).
Node.js / React (Dashboard & Server)
Backend (server.ts): Uses Express.js to serve REST APIs (/api/data, /api/runs), and better-sqlite3 to safely read the SQLite database.
Frontend (App.tsx): Built with React and styled heavily with Tailwind CSS.
Charts: Uses Recharts for the interactive line and area charts.
Icons: Lucide-React for crisp SVG iconography used in the sidebar and KPI cards.
